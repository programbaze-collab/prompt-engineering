# LLM-as-a-judge: рубрика и её калибровка

**Задача.** Оценивать ответы Telegram-бота из [кейса 1](../01-tool-agent/) там, где не хватает регулярных выражений: решает ли ответ задачу покупателя, следует ли бот своим правилам, понятно ли написано.

**Где работает:** [evals/judge.mjs](https://github.com/programbaze-collab/favorit-parts-search/blob/main/evals/judge.mjs) в favorit-parts-search.

**Модель:** deepseek-chat, температура 0, JSON mode. Судья получает весь диалог и сырые ответы инструментов — чтобы сверять факты, а не верить боту на слово.

## Итоговая рубрика

```
Ты проверяешь ответы Telegram-бота магазина автозапчастей. Бот ищет детали и аналоги по артикулу через API поставщика.

Оцени последний ответ бота по шкале от 1 до 5:
5 — полностью решает задачу пользователя: понятно, коротко, есть всё нужное для решения о покупке (производитель, номер, цена, наличие, срок), или правильно уточняет, если запрос неоднозначен.
4 — решает задачу, есть мелкие недочёты: лишние слова, неудачный порядок.
3 — частично решает задачу: чего-то важного не хватает или ответ трудно читать.
2 — почти не помогает пользователю.
1 — не отвечает на вопрос, вводит в заблуждение или противоречит данным инструментов.

Правила бота, которые нужно учитывать:
- цены, остатки и сроки — только из данных инструментов;
- если по артикулу несколько производителей, а нужный не назван, бот перечисляет их и спрашивает. Если пользователь назвал производителя (в любом регистре, в любом месте сообщения), уточнять не нужно — бот сразу отвечает про этого производителя, и это правильно;
- если артикула нет, бот просит его прислать;
- если инструмент вернул ошибку, бот объясняет её простыми словами;
- аналогов показывает не больше пяти, самые дешёвые в наличии;
- пишет по-русски простым текстом без Markdown.

Поля в данных инструментов: stock — общий остаток по всем складам, minPrice — минимальная цена, bestWarehouse — самый дешёвый склад с его собственным остатком.

Сверяй факты в ответе с данными инструментов. Ответь JSON: {"score": число от 1 до 5, "reason": "одно-два предложения по-русски"}.
```

## Как устроено

- **Каждый балл описан словами.** «Оцени от 1 до 5» без описания даёт оценки, которые нельзя сравнить между прогонами.
- **Судья знает правила бота.** Иначе он оценивает ответ по своим представлениям о хорошем ответе, а не по требованиям продукта.
- **JSON с обоснованием.** `reason` нужен, чтобы разбирать несогласие с судьёй: по нему видно, ошибся бот или рубрика.
- **Сценарий пройден, только если прошли и проверки кодом, и судья (оценка ≥ 4).** Судья — не единственный контроль.

## Калибровка: где судья ошибался

Ответы судьи тоже надо проверять. Все случаи ниже найдены разбором `reason` у оценок, которые расходились с автоматическими проверками.

| Что случилось | Причина | Что сделал |
| --- | --- | --- |
| Бот округлил все цены («213 ₽» вместо «213,71 ₽») — судья поставил **5** | Модель плохо сверяет цифры в длинном тексте | Цены проверяет код: каждая цена в ответе должна быть в ответах инструментов. Судья за цифры не отвечает |
| Бот написал «86,71 ₽» вместо «86,88 ₽» — судья поставил **5** | То же | То же |
| Судья снизил оценку до 3: «в ответе 846 шт., а в инструменте 9» — хотя 846 правильный общий остаток | Судья не знал, что значат поля `stock` и `bestWarehouse` | Описание полей в рубрике |
| Судья ставил 3 за то, что бот не переспросил производителя, хотя пользователь написал «сколько стоит ASAM 01089?» | Правило «если производителей несколько — спроси» было сформулировано без исключения | Уточнил правило: если производитель назван, уточнять не нужно |

После калибровки: 45 из 45 прогонов, средняя оценка 4,89 из 5.

## Выводы

1. **LLM-судья пропускает фактические ошибки в числах.** Факты, которые можно проверить кодом, нужно проверять кодом. Судья — для того, что кодом не проверить.
2. **Расхождение судьи и автоматических проверок — сигнал.** Каждое такое расхождение оказывалось либо ошибкой бота, либо дырой в рубрике.
3. **Ограничение:** судья — та же модель, что и бот, и может разделять его ошибки. Следующий шаг — судья на другой модели и ручная разметка части ответов, чтобы измерить согласие судьи с человеком.
