# SEO-мета в JSON с ограничениями длины

**Задача.** Для каждой страницы мини-сайта бренда на [wiki-brand.com](https://wiki-brand.com) нужны meta title и meta description: title до 48 символов (сайт сам добавляет название), description — 140–160 символов. Длина критична: короче — поисковик дописывает текст сам, длиннее — обрезает на полуслове.

**Модель:** deepseek-chat, температура 0,5, JSON mode.

## Проблема

Языковая модель не умеет надёжно считать символы: она видит текст токенами, а не буквами. Просьба «напиши описание ровно 140–160 символов» даёт то 120, то 190 — и повтор с замечанием «слишком длинно» помогает плохо.

## Решение: модель даёт варианты, код выбирает

Вместо одного ответа модель возвращает несколько вариантов каждого поля, а код выбирает тот, что попал в окно длины:

```
Return strict JSON: {"pages":[{"id":"...","titles":["...","...","..."],"descriptions":["...","...","...","..."]}]}
with one entry per page below, in the same order.

titles: three variants for the same page, each 25 to 48 characters, naming the brand and the specific topic
of that page, no call to action, no ALL CAPS, no emoji, and no site name (the site appends " | WikiBrand" itself).

descriptions: four variants for the same page, each 140 to 160 characters long (count the characters of every
variant before answering — a variant outside the window is unusable), factual, written for a reader scanning
search results, mentioning the brand once, with no prices, no call to action and no question marks.
Make the four variants genuinely different, not rewordings of one sentence.
```

Код:

1. Берёт первый title не длиннее 48 символов.
2. Для description проверяет каждый вариант: подходящий по длине берёт как есть, слишком длинный обрезает по концу предложения, затем по запятой, затем по границе слова — если после этого он не короче 140 символов. Короткие варианты отбрасываются: дописывать текст за модель код не должен. Из подошедших выбирает самый близкий к середине окна — 151 символ.
3. Если ни один вариант не подошёл — пробует мету, которая уже опубликована для страницы.
4. Если не подошла и она — один повтор с критикой: «каждой странице нужен хотя бы один title до 48 символов и хотя бы одно описание, которое действительно 140–160 символов — посчитай каждый вариант перед ответом». Не помогло — файл не записывается, страница попадает в список ошибок.

## Почему промпт устроен так

- **Все страницы бренда — одним запросом.** Модель видит, какой интент у каждой страницы, и не пишет восемь одинаковых описаний. Каждой странице передаётся её кластер запросов: «own the intent …».
- **«Genuinely different, not rewordings».** Без этого четыре варианта отличаются одним словом и одинаково не попадают в окно длины. Разные по построению варианты — разная длина — выше шанс попасть.
- **«Count the characters … a variant outside the window is unusable».** Модель объясняет себе, зачем ограничение, — но точность подсчёта это не гарантирует, поэтому выбор всё равно делает код.
- **Сайт сам добавляет название.** Иначе модель вписывает «WikiBrand» в title и съедает лимит.
- **Запреты под формат выдачи:** без вопросительных знаков, призывов и цен — description читают в выдаче поисковика, и это энциклопедия, а не магазин.

## Выводы

1. **Если модель плохо делает операцию — не проси её, а дай коду.** Подсчёт символов, как и форматирование цен в [кейсе 1](../01-tool-agent/), — работа для кода.
2. **Несколько вариантов + детерминированный выбор** — дешёвый приём, который превращает «иногда попадает в ограничение» в «почти всегда попадает».
3. **Всегда есть запасной путь:** если ничего не подошло, используется прежняя мета, а если нет и её — файл не перезаписывается. На сайт не попадает пустое или обрезанное на полуслове описание.
