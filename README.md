# Промпт-инжиниринг: кейсы

Максим Макаров · Telegram [@programbaze](https://t.me/programbaze)

Пять промптов из рабочих проектов. В каждом кейсе — задача, промпт, ошибки модели, найденные на практике, что изменено и как проверено. Цифры — из прогонов на тестовых наборах, а не оценки на глаз.

| 1 | [Агент с инструментами: подбор автозапчастей](01-tool-agent/) | Системный промпт агента с вызовом функций, порядок вызовов, перенос правил из промпта в данные инструментов | 15 эталонных диалогов × 3 прогона: 14/15 → 45/45 |

## Подход

1. **Сначала набор тестов, потом промпт.** Без измерения непонятно, что чинить: в кейсе 5 ожидал проблем с ловушками, а ошибки оказались в нормализации.
2. **Что можно проверить кодом — проверяет код.** Цены, длина, формат, запрещённые слова. LLM-судья — только для того, что кодом не проверить, и его тоже надо проверять (кейс 2).
3. **Не заставлять модель делать то, что она делает плохо.** Форматирование чисел и подсчёт символов — работа для кода (кейсы 1 и 4).
4. **Запрет в промпте не гарантирует поведения.** Нужны пример, причина правила и проверка результата.
5. **Отложенный набор.** Результат на данных, на которых отлаживался промпт, ничего не доказывает.
